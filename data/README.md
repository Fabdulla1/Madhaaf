# Dictionary annotations (20 October 2026)

`dictionary-annotations-20261020.csv` records the project owner's 366-row Kutchi/English list as 374 entries, plus the site's pre-existing `hadaa ach` entry. The attachment's SHA-256 is `b6478b8a43bc5d3e0004647632b11d4fa5243361a3072b3c5d2466f6ab33298d`. Rows 347–367 are the 21 additions in this update; the earlier rows were already imported. Comma-separated Kutchi alternatives are separate entries, comma-separated English glosses are separate senses, and the two meanings of `pun` remain separate homographs.

Part-of-speech labels are **provisional inferences from the supplied English glosses**. The labels use familiar broad categories described by [Universal Dependencies](https://universaldependencies.org/u/pos/all.html), but they have not been validated against Kutchi sentences. The English glosses do not establish Kutchi inflection, gender, number, or etymology, so the import does not invent those properties. A blank part of speech and `Word class to review` mark 15 cases where the English gloss alone could fit more than one class. Tags such as `Food & drink` are meaning domains; tags such as `Possessive`, `Formal register`, `Homograph`, and `Multiword expression` record properties supported by the source wording or spelling. Every entry carries `Provisional analysis` until a speaker reviews it.

The CSV preserves the source row numbers and includes explicit review notes for `kachar`. The source gives it both an animal meaning and an insult meaning; the site presents both senses with a register warning rather than conflating them. Existing meanings, example sentences, and identifiers are retained. No full definitions or example sentences have been added from these short glosses.

`scripts/apply_dictionary_annotations.py` performs a dry run by default. Applying it requires `psycopg` 3, a production `.env.local` containing `madhaaf_db_POSTGRES_URL_NON_POOLING`, and `--apply --backup-dir` with a directory outside the repository. It writes a complete dictionary snapshot there, then updates and publishes the records atomically. A second dry run should report zero new entries. Keep backups and environment files out of Git.
